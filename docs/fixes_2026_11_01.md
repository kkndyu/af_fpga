# Loader/readback fixes, 2026-11-01

## Changes

- READ_W reply countdown now starts at rows times 32 bytes, so tlast marks the
  actual final byte. Previously it started at the row count and ended the first
  Ethernet packet early.
- Payload parsing records length minus one while receiving the header. The
  payload-to-CRC transition compares bcnt directly against that register,
  removing the increment-before-compare operation from the measured critical
  loader path. Zero-length commands still skip the payload state.
- Builds reject missing or negative setup/hold slack before writing a bitstream.
- Named build outputs preserve previous artifacts. Optional bank3 mode includes
  only the 256-register bank-3 receiver pblock, without the eight lane-pair boxes
  used in the previous experiment.
- Ethernet simulation now checks compile/elaboration exit codes and uses the
  same cleanup/return path as other simulation targets.

## Simulation: PASS

All seven targets passed: Ethernet shim, AXI bridge, loader, UART, result
readout, GEMV engine, and board. Board simulation checks the initial unloaded

The loader regression now checks tlast and compares all 256 result lanes with
ref_out.hex. New READ_W cases check both bytes and the unique final tlast:

| Rows | Bytes | Consumer | Accepted tlast index |

| 4 | 128 | Fast | 127 |
| 32 | 1024 | One byte per 256 cycles | 1023 |

The Ethernet shim checks 32-, 300-, and 1024-byte replies including a producer
pause in the middle, exact payload lengths, and every payload byte.
